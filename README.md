# HRM Workforce Allocation — 가상 데이터 분석 시연

**현대오토에버 HRM 과제 준비를 위한 비공식·독립 시연입니다.** 프로젝트, 직원, 기술역량, 근무시간, 배정 결과는 **모두 가상 데이터**입니다. 현대오토에버의 실제 조직 현황·직원별 역량·인력 부족을 나타내지 않습니다.

## 무엇을 구현했나요?

- 가상 프로젝트 **3개**, 가상 ITO 직원 **4명**, 2027년 **1~6월**, 기본/추가 수주 **2개 시나리오**
- `pandas`로 시나리오·월별 업무시간 합산, 12 FTE × 월 120시간의 SI 투입 가능시간 비교
- 기술태그 일치, 직원별 월간 투입 상한, 필수 온콜 직원 제외, ITO 필수 운영시간 보존
- `scipy.optimize.linprog`를 사용한 **재배치 가능한 총 업무시간 최대화**(월별 독립적인 선형계획법)
- 입력 중복·누락·음수·허용 기술태그·재배치 상한 및 결과 합계 검증
- SI의 직원 1명당 월 110/120/130시간 가정에 따른 단순 민감도 분석

**주의:** 이 코드는 고객 납기·직원 숙련도·보상·외부인력 비용·채용 정원을 최적화하지 않습니다. SI 투입 가능시간은 프로젝트별 예상 업무량의 비중에 따라 배분하는 **단순화된 가정**으로, 실무 배정계획을 대체할 수 없습니다.

## 실행 방법

Python **3.10 이상** 권장:

```bash
python -m pip install -r requirements.txt
python run_analysis.py
python check_ai_tags.py
python -m unittest discover -s tests -v
```

- `run_analysis.py`는 **`data/*.csv` 입력을 읽어** `outputs/*.csv` 결과를 새로 생성합니다. 원본 입력 파일은 덮어쓰지 않습니다.
- `data/config.json`에는 대상 월·시나리오·SI FTE·월 투입시간·허용 기술태그가 있습니다.
- 데이터를 변경해서 다른 가상 시나리오를 시험할 때에는 `python run_analysis.py --skip-reference-check`를 사용하세요. 변경하지 않은 원본에서는 기본 실행의 PPT 수치 일치 검사가 작동합니다.
- `requirements.txt`의 버전은 호환 범위입니다. 실무 운영용으로 버전을 엄격히 고정한 환경은 아닙니다.

## 발표자료와 대조한 결과

| 분석 기간 | 초기 부족 | 제약조건을 반영한 재배치 | 잔여 부족 |
|---|---:|---:|---:|
| **기본 수요 / 6개월** | 600시간 | 100시간 | **500시간** |
| **추가 수주 / 6개월** | 1,440시간 | 100시간 | **1,340시간** |

**1월(기본 수요)** 예상 업무량 1,800시간 − SI 가용시간 1,440시간 = 초기 부족 **360시간** → 가상 재배치 **40시간** → 잔여 부족 **320시간**.

1~2월 재배치 총 100시간은 E031(1월 40시간·2월 40시간), E032(2월 20시간)의 가상 기술태그·투입 상한·필수 운영시간을 반영한 모델 결과입니다. E033은 필수 온콜 업무, E034는 기술 불일치로 제외합니다. **3~6월 ITO의 남는 시간을 0으로 설정한 가정**을 포함합니다.

## AI 활용 범위 — 과장하지 않도록 구분

- **생성형 AI로 작성한 검토 초안**: `data/ai_tag_review.json`. 가상의 업무/직원 설명을 기술태그로 분류한 예시이며, 실무 적격성의 실측 검증이 아닙니다.
- **생성형 AI 보조 코드 개발**: 분석 목적과 조건에 맞춰 코드 초안을 생성·수정한 뒤 Python으로 실행 결과를 검증했습니다.
- **자동화된 시스템은 아님**: `run_analysis.py`는 CSV에 **사전 입력된 기술태그**를 사용합니다. LLM API 호출, 분류 정확도 평가, 실제 사내 데이터 연동 또는 인력 배정 승인은 **구현하지 않았습니다**.
- `check_ai_tags.py`는 AI 예시의 원문·허용 태그·분석 입력값의 **일치 여부만** 확인합니다. **AI 분류의 의미상 정확도나 직원의 숙련도를 검증하는 프로그램은 아닙니다.**

## 수리모형의 범위

각 월의 직원 `i`, 프로젝트 `j`에 대한 배정시간 `x_ij ≥ 0`을 결정합니다.

**목적함수**: `maximize Σ_i Σ_j x_ij` — 조건을 만족하는 배정시간 합계 최대화.

**제약조건**:
1. 요구기술과 보유기술이 불일치하거나 필수 온콜 직원이면 배정 불가.
2. 각 직원의 월간 이동 가능시간 이내 배정.
3. SI 기존 가용시간을 프로젝트 수요 비중으로 먼저 배분한 뒤, 각 프로젝트의 잔여 업무시간 이내 배정.
4. ITO 전체 가용시간 − ITO 필수 운영시간 이내 배정.

이 모델은 매월 독립 실행됩니다. 근무자별 기술 숙련도, 채용 리드타임, 고정비, 외주비, 인력 이동에 따른 생산성 차이, 프로젝트 사이 선후행 관계 및 고용·노무 문제는 반영하지 않았습니다.

## 검증 범위

`tests/test_analysis.py`는 기본 수치 재현, 직원별 상한, 온콜 제외, 기술 불일치, ITO 운영시간 부족, 공급 충분한 경우, FTE 민감도, 입력 중복·음수 오류, AI 예시의 입력 일치 여부를 확인합니다. 이는 **가상 조건하 구현 검증**이며 실제 인사 운영 효과의 검증은 아닙니다.
